# Purifier：iOS 阅读代理模式

> 起因：移动端网络差，点开一条 HN / RSS / TG 里的外链，原网页拖着 CSS、JS、
> 追踪脚本和大图慢慢爬。iOS 设置里加一个 Purifier 开关，开启后 app 内所有外链改走
> `https://<server>/p/<host>/<path>?<query>`，由服务端抓取目标页并处理成一个**尽量不
> 依赖外部资源、纯粹用于阅读**的页面。例：`https://news.ycombinator.com/item?id=49537553`
> 在 iOS 点开时变成 `https://condenser.reorx.com/p/news.ycombinator.com/item?id=49537553`。
>
> 本 plan 记录已定决策、URL 与鉴权契约、三种渲染模式及其调度、后端与 iOS 的落地
> 蓝图、测试先行清单、调研实测，以及验收与发布注意。**只做 iOS + 后端，web 端不做**
> ——这个功能就是为移动端弱网服务的。

## 0. 已定决策（用户拍板，不再重议）

1. **鉴权走"一次性票据换 cookie"**：iOS 用设备 token 向 `/api/purifier/ticket` 换一张
   5 分钟票据拼进 URL；服务端验票后种一个独立的 30 天 `condenser_reader` cookie 并
   302 到干净 URL。`/p` `/pa` 只认这个 cookie 或现有的 web 登录 cookie，不认 Bearer
   （浏览器导航和 `<img>` 请求本来就带不了）。不做无鉴权：那等于向全网开一个抓取代理，
   还替陌生人烧 pure.md 配额。
2. **三种渲染模式，白名单挑 `proxy` 还是 `readable`，`readable` 自带 `puremd` 兜底**：
   - `proxy`：整页保留、剥 JS、静态资源与链接全部改写进代理。HN 这类要保留讨论层级
     的站点走这里（`news.ycombinator.com → proxy`）。
   - `readable`（**默认**）：`readability-lxml` 抽正文 + 同样的资源改写 + 我们自己的
     阅读模板。图片保留、零配额、无第三方。
   - `puremd`：**只作为 `readable` 的兜底**——上游拒绝（403/429/5xx、非 HTML、抓取异常）
     或抽出的正文明显太少（< 500 字，可配）时，改用 pure.md 的 Markdown 渲染。
     pure.md 丢图（`![alt](IMAGE)` 占位符，URL 不可得）、走第三方、有配额，所以不当默认。
3. **JS 永远剥掉**。`/p/` 页面跑在 condenser 同源，允许第三方 JS 执行等于把 30 天 cookie
   交给它去调 `/api/*`。"允许 JS"只做服务端环境变量 `CONDENSER_PURIFIER_ALLOW_JS`
   （默认 false），不做成 iOS 开关；即使打开也下发 CSP 限制 `connect-src` /
   `frame-src` / `form-action`。对 SPA 站点不友好是已接受的代价。
4. **iOS 不改写的链接只有三类**：X（`x.com` / `twitter.com`，保留深链进 X app）、`t.me`、
   非 http(s) scheme。HN `/user` 页也走 purifier，无害。
5. **缓存**：进程内 TTL 缓存（1 小时，按上游 URL + 模式），不加表。资源不在服务端缓存，
   靠响应头 `Cache-Control` 让 Safari 缓存。
6. **web 端不做**。`vibeReader.ts` 的文档级点击委托是现成模板，但改写后链接变同源会让
   Vibe Reader 的 `shouldAnnounce` 跳过它，两者互斥；且 web 不是弱网场景。
7. **规则表写在代码常量里**（`purifier.py` 的 `MODE_RULES`），环境变量覆盖等有需求再加。
8. 其余细节按本 plan 推荐执行。

## 1. URL 契约

| 形态 | 含义 |
|---|---|
| `GET /p/<host>/<path>?<query>` | 文档：按模式渲染成阅读页 |
| `GET /pa/<host>/<path>?<query>` | 资源：只放行 `image/*`、`text/css`、`font/*`，原样透传（CSS 内的 `url()` / `@import` 改写后再透传），带 `Cache-Control: private, max-age=86400` |
| `GET /api/purifier/ticket` | 换票（`require_auth`：Bearer 或 cookie），`{"ticket": "...", "ttl": 300}` |

- **scheme**：URL 里不区分。一律先 https；只在**传输层连不上**（`ConnectError` /
  `ConnectTimeout`）时回落 http 重试一次；HTTP 状态错误、读超时是对方给出的真实回答，
  不重试。绝大多数 http 原链接会被对方 301 到 https，这条回落只兜极少数纯 http 站。
- **host** 允许带端口（`host:8080`）；小写归一（iOS 侧和后端都做），避免同一站点两份缓存。
- **path / query 按原始字节转发**。后端从 `request.scope['raw_path']` 取未解码的路径
  （Starlette 路由参数已经 percent-decode 过，`%2F` 会和 `/` 混淆），query 用
  `request.url.query` 原串，剥控制参数时用正则删除而不是 `parse_qsl` 重编码
  （否则原站参数会被重排、重编码）。
- **控制参数**（带下划线前缀，避免与原站参数撞名）：`_pt=<ticket>`（换票，用后即
  302 剥掉）、`_mode=proxy|readable`（模式覆盖，工具栏"整页模式"链接用它；`puremd`
  不可手动指定——它是兜底，不是选项）。
- **fragment** 客户端自行保留（浏览器不会发给服务端，代理页若复用了原文锚点 id 就白赚）。
- **不再包一层**：`href` 已经指向 condenser 自身（`/p/`、`/pa/`、`/api/`）的不动；
  `EXCLUDED_REWRITE_HOSTS = {x.com, twitter.com, t.me}` 在页内也保持原链接（点开去
  X app / Telegram，不进代理）。
- **拒绝的 host**：无点号的裸名、IP 字面量、`localhost`、以及 condenser 自己的域名——
  五行代码挡掉最明显的自环与内网探测；更完整的 SSRF 防护与 `preview.py` 保持同一姿态
  （单用户自托管、已鉴权，不做）。

## 2. 鉴权：票据 → cookie

```
iOS: GET /api/purifier/ticket  (Authorization: Bearer <device token>)
     → {"ticket": "<TimestampSigner, salt=purifier-ticket>", "ttl": 300}
iOS: 打开 /p/host/path?orig=1&_pt=<ticket>
服务端: verify_purifier_ticket(max_age=300) 通过
     → Set-Cookie: condenser_reader=<TimestampSigner, salt=purifier-reader>; 30d; HttpOnly; SameSite=Lax; Secure(生产)
     → 302 /p/host/path?orig=1        （只剥 _pt）
之后 30 天内：/p、/pa 靠 condenser_reader（或现有 condenser_session）通过，不再需要票
```

- `crypto.py` 新增两对签名函数，各用**独立 salt**（`_PURIFIER_TICKET_SALT` /
  `_PURIFIER_READER_SALT`）：票据签名不能冒充 reader cookie，reader cookie 不能冒充
  app 会话 cookie。三个 salt 互不通用，测试要 pin 交叉验证失败。
- `auth.py` 新增纯谓词 `reader_authenticated(request, settings) -> bool`：认
  `condenser_reader` 或 `condenser_session`。不是 `Depends` 抛异常的依赖，因为 `/p`
  `/pa` 失败时要渲染一个**小 HTML 401 页**（Safari 里看到 JSON 不像话），不是 JSON。
  不复用 `require_cookie_auth`——它专属设备管理端点，必须拒绝 reader cookie。
- `SFSafariViewController` 与 Safari 共享 cookie 存储，所以票据只需换一次；Mac
  Catalyst 直接开系统浏览器，同理。
- iOS 侧票据永远是"锦上添花"：点击永远同步、永远用当下缓存的票（可能为 nil）；cookie
  已种下后 `_pt` 缺失不影响。唯一裸奔窗口是开关刚打开的 1 秒内立刻点链接——接受，
  不用同步阻塞去堵。

## 3. 渲染模式与调度

```
resolve_mode(host, _mode) :  _mode 合法 → 它；否则 MODE_RULES[host]；否则 readable
MODE_RULES = {'news.ycombinator.com': 'proxy'}

proxy    : fetch → sanitize_and_rewrite_proxy → 注入工具栏
readable : fetch → extract_readable (readability) → 长度 ≥ min_chars ? 模板 : 兜底
           fetch 失败 / 非 HTML / 抽不出 → 兜底
兜底      : puremd 可用(有 key) → fetch_puremd → parse → markdown-it → 模板(mode=puremd)
           puremd 不可用 → 有短正文就照样显示 + 提示；完全没有就错误页（带原链接 + 整页模式链接）
```

**proxy 模式的处理清单**（lxml 遍历一遍，不用正则改 HTML——`text.py` 记着正则在
不闭合的 `<script>` 上是二次方的）：

- 删：`<script>`（除非 `allow_js`）、所有 `on*` 属性、`javascript:` href、`<iframe>` /
  `<object>` / `<embed>`、`<meta http-equiv=refresh>`、`<base>`（先取值用于 URL 解析，
  再删——留着会劫持我们改写后的根相对链接）、`<link rel=preload/prefetch/preconnect/dns-prefetch>`。
- 改写到 `/pa/`：`img[src]`、`img[srcset]` / `source[srcset]`（逐候选改 URL、保留描述符）、
  `link[rel=stylesheet][href]`、`video[poster]`、`<style>` 文本与 `style=""` 属性里的
  `url()`（`data:` 直通）。
- 改写到 `/p/`：`a[href]`、`form[action]`——HN 的翻页 `?p=2`、`item?id=`、`reply?…`
  都留在代理里。
- 补 `<meta name=viewport>`（缺失时）；`<head>` 顶部插工具栏样式，`<body>` 顶部插工具栏。
- **已知降级**：HN 的评论折叠 `[–]` 是 `href="javascript:void(0)"` + `hn.js` 的
  onclick，剥 JS 后不可折叠；投票、回复要登录，本来就不可用。翻页、评论链接、用户页正常。

**readable 模式**：`Document(html).summary(html_partial=True)` + `short_title()`；
readability **不会**把相对 URL 转绝对，抽出的片段要再过一遍同样的改写（针对同一个
`resolve_base` 结果），否则图片和链接全断。套我们自己的模板：系统字体栈、限宽居中、
`prefers-color-scheme` 深色、全部内联 CSS、零外部资源。

**puremd 兜底**：`GET https://pure.md/<url>`，头 `x-puremd-api-token`。返回
`text/plain` 的 Markdown，顶部 YAML frontmatter 固定三键（`title` / `url` /
`description`，手写解析，不为它引 pyyaml）。`![alt](IMAGE)` 先替换成 alt 文本再交给
`markdown-it-py` 渲染（顺序反了要重新解析 `<img>`）。fence：`CONDENSER_PUREMD_API_KEY`
为空 = 兜底关闭。速率 Starter 档 60/分，单用户够用；不重试 429。

**工具栏**（三种模式都有，一行，内联样式）：`原网页 ↗`（`target=_blank`，原始 URL）·
模式名 · readable/puremd 模式下多一个 `整页 →`（同 URL 加 `_mode=proxy`）。
SFSafariViewController 地址栏只显示 condenser 域名，没有这一行读者回不到原页。

**编码**：header 有 `charset` 用它；没有就窥探前 2KB 的 `<meta charset>` /
`http-equiv`；再没有才 utf-8。比 `preview._charset` 多一步，因为 CJK 站点常常只在
`<meta>` 里声明。

**压缩**：线上 Caddy 的 condenser 站点块没有 `encode`，压缩目前全靠 Cloudflare 边缘。
app 内加 `GZipMiddleware(minimum_size=1024)` 兜底——HN 一个 665 评论的讨论页原始
HTML 962KB，弱网下必须压。全局中间件，API JSON 顺带受益。

### 4.2 配置

```python
# --- purifier (purifier.py) ---
condenser_purifier_max_bytes: int = 5_000_000        # 文档上限；proxy 模式整页保留，HN 大帖近 1MB
condenser_purifier_cache_ttl: int = 3600             # 进程内文档缓存
condenser_purifier_min_readable_chars: int = 500     # readable 抽出正文低于此 → puremd 兜底
condenser_purifier_allow_js: bool = False            # 唯一保留 <script> 的途径；true 时下发 CSP
condenser_purifier_asset_cache_seconds: int = 86400  # /pa 响应的 Cache-Control
condenser_puremd_api_key: str = ''                   # 空 = 兜底关闭（同 attr/summary key 的"key 即开关"惯例）
```
资源字节上限复用 `condenser_preview_image_max_bytes`；抓取的 UA / 超时 / 重定向复用
`condenser_preview_*`。

### 4.3 关键签名

```python
# URL
def parse_target(host: str, raw_path: str, raw_query: str) -> Target        # 路由参数 → 上游 URL 材料（校验 host、剥控制参数）
def rewrite_url(href: str, base_url: str, own_origin: str, kind: Literal['p','pa']) -> str
    # 一处决策，所有属性共用：空/#/非 http(s) → 原样；排除 host / 自身 → 绝对 URL 不包；其余 → /{kind}/host/path?q#f
def rewrite_css(css: str, base_url: str, own_origin: str) -> str
def rewrite_srcset(value: str, base_url: str, own_origin: str) -> str
def resolve_base(raw_html: str, final_url: str) -> str                     # 尊重 <base href>
def resolve_mode(host: str, override: str | None) -> Mode

# 抓取（可注入，测试零网络）
FetchPage = Callable[[str, Settings], Awaitable[tuple[str, str, bytes]]]   # url → (final_url, content_type, body)
async def fetch_page(url, settings, *, cap, accept) -> ...                  # https → 传输层失败才回落 http；底层是 preview._fetch_capped
FetchPuremd = Callable[[str, Settings], Awaitable[str]]

# 渲染
def sanitize_and_rewrite_proxy(html: str, base_url, own_origin, *, allow_js) -> str
def sanitize_and_rewrite_fragment(body_html: str, base_url, own_origin) -> str   # readable 片段共用
def extract_readable(html: str, base_url, own_origin) -> tuple[str, str, int] | None   # (title, body_html, text_chars)
def parse_puremd(raw: str) -> tuple[str | None, str | None, str]
def render_puremd_html(markdown: str) -> str

# 编排（模块里唯一 broad-catch 边界：readable 失败 → puremd）
async def render_document(target, settings, *, own_origin, mode_override=None, fetch_page=None, fetch_puremd=None) -> DocumentResult
async def render_asset(target, settings, *, own_origin, fetch_page=None) -> AssetResult
```

`render_asset` 刻意不是 `render_document` 的第四种模式：CSS 要改写但绝不能进
`lxml.html` / readability，图片字节更不能；CSS 内的 URL 要针对**样式表自己的** final_url
解析，不是父文档的。

错误类型：`PurifierError` → `UpstreamFetchError` / `NotHTMLError` / `PuremdError` /
`PuremdUnavailable` / `BadTargetError`。低层函数只抛；router 是 broad-catch 边界，
映射成 401 / 400 / 502 的小 HTML 页（每页都带原链接）。

### 4.4 测试先行（BDD）— `tests/test_purifier.py`

照 `tests/test_preview.py` 的形状：纯函数 → 注入 seam → `TestClient` 行为。

- **URL 助手**：host/path/query 拆合；`raw_path` 保留 `%2F`；userinfo 剥掉；端口 / IDN；
  拒绝 IP、localhost、无点号、自身域名；`_pt` / `_mode` 只剥自己、其余字节不动；
  `rewrite_url` 的 8 个分支（普通链接 → `/p`、资源 → `/pa`、query+fragment 保留、
  `mailto:` / `javascript:` / `data:` / `#x` 原样、排除 host 保持绝对、自身 `/p` `/pa`
  `/api` 不双包、相对路径对 base 解析、`<base href>` 生效）；`resolve_mode` 三级优先。
- **CSS / srcset**：`url()` 与 `@import` 改写、`data:` 直通、引号三态；srcset 每个候选改
  URL、描述符原样。
- **proxy 清洗**：script / on* / javascript: / iframe-object-embed / meta refresh / base /
  preload 全删；img src+srcset、stylesheet href、`<style>` 与 `style=""`、video poster、
  a href、form action 改写；缺 viewport 补上；工具栏注入且含原链接；`allow_js=True` 保留 script。
- **readable**：标题 + 正文；片段内相对图片被改写；模板含深色 CSS、无外部资源；解析失败
  返回 None；字数统计。
- **puremd 兜底**：正文太短 → 兜底；非 HTML → 兜底；抓取异常 → 兜底；4xx/5xx → 兜底；
  无 key → 不静默，显示短正文 + 提示 / 错误页；frontmatter 解析；`(IMAGE)` → alt 文本。
- **抓取 scheme 重试**：先 https；`ConnectError` 才回落 http；HTTP 状态错误不回落。
- **编码**：header charset > meta charset > utf-8。
- **缓存**：命中跳过第二次抓取；TTL 到期；key 含模式。
- **Router / 鉴权**：ticket 端点要 `require_auth`、返回可验票据；`/p` 无 cookie 无票 →
  401 HTML；有效票 → 种 `condenser_reader` + 302 且 URL 只少了 `_pt`；过期 / 伪造票 →
  401；现有 `condenser_session` 也通过；`/pa` 同样门禁；`/pa` 拒绝 `application/javascript`；
  `/pa` 带长 `Cache-Control`；HN host → proxy；默认 → readable；`_mode` 覆盖；原站 query
  原样转发；`allow_js` 时有 CSP 头；`/p` 不被 SPA 兜底吞掉（有 `frontend/dist` 时也 404
  → 我们的路由）。
- **crypto**：三个 salt 交叉验证全部失败。

### 5.2 `purifiedURL` 的坑

- 用 `URLComponents.percentEncodedPath` / `percentEncodedQuery`，**不用 `.path`**
  （已解码，`%2F` 会变成分隔符）、不用 `URLQueryItem` 重建 query（二次编码）。追加票据
  是字符串拼接 `q + "&_pt=" + ticket`。
- host 小写；非默认端口按 `host:port` 拼进路径段；空 path 不补 `/`；fragment 透传到末尾。
- 排除：非 http(s)、host 缺失、`isPurifierExcludedHost`（x.com / twitter.com 及
  `www.` `mobile.` `m.` 变体，t.me）、与 base 同源。

## 6. 调研记录

**pure.md 实测**（2026-09-07，token 在 `tmp/puremd.env`，Starter 档）：
`GET https://pure.md/<url>` + `x-puremd-api-token`；`text/plain`，Markdown 带 YAML
frontmatter（`title` / `url` / `description` / `access_date`）；**图片一律 `![alt](IMAGE)`，
URL 丢失，文档无任何参数可保留或改输出 HTML**；`x-ratelimit-remaining: 59`，响应
`s-maxage=3600`；HN 讨论页 199KB，评论压成多层 `>` 引用，能读但层级难辨——印证 HN 自渲染。
错误码 400 / 415 / 429。

**readability-lxml 实测**：博客文 8.4K 字符、4 图保留、`short_title()` 干净；Google
模型卡 7K 字符；HN 讨论页抽出的是评论碎片（15K 字符、336 张 `s.gif`）——正是 HN 不能
走 readable 的原因。

**HN 页面**：665 评论的帖子 962KB，静态资源只有 `news.css` + `hn.js` + `s.gif` 缩进图，
链接全是相对路径（`item?id=`、`reply?id=&goto=`、`?p=2`）。proxy 模式天然适配。

**开源方案**：Mozilla Readability / Defuddle（JS，需 Node 运行时）、Trafilatura（Python，
抽正文最准但面向文本）、Endler 的 `readable`（Rust，URL 前缀式 reader proxy，思路相同）、
`readability-server` 等 Docker REST 服务。都要引新运行时或新服务，而"整页改写 + 资源
代理"没有现成 Python 组件；我们已有 `readability-lxml` + `lxml`，自写核心就是一次 lxml
遍历 + URL 改写。不引入。
