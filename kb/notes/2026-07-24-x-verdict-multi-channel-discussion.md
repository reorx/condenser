## 单通道 dense kNN 的两个结构性缺陷（用户指出）

1. **信用分配（credit assignment）**：down 一条长推，标签打在整个「袋子」上，但成因可能只是其中某个「实例」（一句营销话术）。正式名字：**多示例学习（MIL）**——标签在 bag 级、成因在 instance 级。检索界对应物：ColBERT 式 late interaction（保留 token/句子级向量做 MaxSim）。
2. **向量纠缠（entanglement，更致命）**：embedding 按语义/话题相似训练，**文风在向量里只占很弱分量**。两条话题不同、但都是 AI slop 腔的推文在向量空间里离得很远——down 了十条 AI slop，换个话题的第十一条照样漏网；反过来因「营销味」down 一条 LLM 话题的推会误伤整个 LLM 邻域。dense kNN 天生混淆「讨厌这个话题」和「讨厌这种说话方式」。

## 第一次回测（2026-07-27）：纠缠不是理论，是负判定的死因

标注攒到 30 👍 / 29 👎 后，对生产库快照做留一法回测（`scripts/x_verdict_backtest.py --sweep`
+ `tmp/x_verdict_variants.py`）。**缺陷 2（向量纠缠）在数据上坐实了**：

- 正判定 D0.60 / M3 / `>=0.25`：**100% 精确**（8 次判定），基率 50.8% —— 有真实信息。
- 负判定：整个网格最好 55.6% 精确，负样本基率 49.2% —— **没有信息**。
- 按 reason 拆召回（D0.60/M3/−0.45）：`promo` 11 个召回 2 个，`engagement_farming` 10 /
  `ai_slop` 3 / `author` 1 / `topic` 1 / 无理由 3 —— **全部 0**。

标签分布本身就是结论：**29 个踩里 24 个是文风判断，`topic` 只有 1 个**。用户按下踩的绝大多数
原因，话题 embedding 结构上就看不见。于是 `CONDENSER_VERDICT_NEGATIVE_ENABLED` 默认 false ——
不是保守，是这一侧确实什么都不知道。

几条给下一轮的提醒：

- **「负样本只取 `reason IS NULL OR topic`」变体不是解法**（至少这个数据量下）：只剩 4 个负
  样本，正判定的 88% 精确其实是 30/34 的基率，即「全判正」的分类器。变体值得留着，但要等
  `topic` 踩本身攒够。
- **chips 的价值提前兑现了**：没有 reason 列，这次只能得到「负判定不准」，得不到「因为标签是
  文风的」。信用分配的诊断价值，比它对模型的直接贡献先到账。
- **通道优先级被数据重排**：C（LLM 属性）> D（n-gram，`engagement_farming` 极其词面化）> A
  （作者先验，只有 1 个 `author` 踩）。原笔记按「成本」排的次序（A 先），按「收益」应该倒过来。
- 正判定这一侧现在是**唯一在产出**的通道，也因此成了将来组合器的基线特征：任何新通道要证明
  自己，先得在留一法上跑赢「只有 B 的正向」。

## 「先提取特征再标记特征」= aspect/attribute-based 建模

标注不只落在「这条推文」上，而是**摊派到它的属性上**。属性两类：

- **话题属性**：crypto、LLM、政治、创业鸡汤……
- **文风属性**：engagement bait、thread 钓鱼（🧵 1/N）、emoji 轰炸、listicle 腔、AI slop 语言特征、推销 CTA……

**LLM 做特征提取器**（不做终审判决）：每条推文 ingest 时一次廉价 LLM 调用吐 `{topics: [...], style_flags: [...]}` 存库、可缓存。这是先前被否掉的「方案 C（LLM judge）」的正确复活方式——LLM 从裁判降级为特征工。属性分数用**朴素贝叶斯 / Beta 平滑计数**维护（垃圾邮件过滤器血统；「识别标志性营销话术」本质就是垃圾过滤问题）。跨话题泛化由此获得：十条话题各异的 down，`ai_slop` 属性累积出笃定负分。

## sparse 向量：要精神，不要基建

SPLADE / BM25 hybrid 是大规模检索的基建，本场景杀鸡用牛刀。sparse 的精神——「具体词面特征单独记账，不被平均进稠密向量」——用零基建实现：**token/n-gram 贝叶斯计数**，一张 `(token, up_count, down_count)` 表，SQLite 天然可做，可解释性拉满。

## 目标架构：多通道弱信号集成

小数据体制（百~千级标注）的正确形态：几个各捕捉一种「讨厌的理由」的简单通道 + 轻量组合器。

```
                        新 For You 推文
                              │
        ┌──────────┬──────────┼──────────────┐
        ▼          ▼          ▼              ▼
   ┌─────────┐ ┌─────────┐ ┌──────────────┐ ┌──────────────┐
   │ A 作者    │ │ B 话题    │ │ C 属性        │ │ D 词面        │
   │ 先验      │ │ dense kNN │ │ LLM 提取      │ │ n-gram 贝叶斯 │
   │          │ │(主计划设计)│ │ topics+style  │ │(垃圾过滤血统) │
   │ 该作者的  │ │           │ │ flags, 每属性 │ │              │
   │ up/down  │ │ 捕捉:     │ │ 贝叶斯计分     │ │ 捕捉:        │
   │ 历史计数  │ │「这类内容」│ │ 捕捉:         │ │「这种黑话」   │
   │ Beta平滑  │ │           │ │「这种做派」    │ │              │
   └────┬─────┘ └────┬─────┘ └──────┬───────┘ └──────┬───────┘
        │            │              │                │
        └──────┬─────┴──────┬───────┴────────────────┘
               ▼            ▼
          ┌────────────────────────┐
          │ 组合器                  │
          │ 冷启动期: 手调权重加权和 │
          │ 数据够后: 逻辑回归 stack │
          │ (4个通道分是特征,        │
          │  标注是监督信号)         │
          └───────────┬────────────┘
                      ▼
        主计划既有闸门体系原样保留:
        证据不足 → neutral / 不对称阈值 / verdict_meta 可解释
```

关键性质：

- **每个通道独立可关、独立可回测**（留一法），让数据决定复杂度。
- verdict_meta 可解释性升级：从「像你 down 过的 3 条」→「作者 −0.7，ai_slop −0.8，话题 +0.2」。

## 非算法杠杆：down-reason chips（性价比之王）

信用分配最便宜的解法是**问用户**：down 时弹 one-tap 理由 chip（可跳过）。对标 YouTube
"Not interested → Tell us why"。改变的是**数据质量**，不是模型。

### 已落地的设计（2026-07-26，schema v9，三端）

原始草案是三个 chip（`[ 话题不感兴趣 ] [ 营销味/AI腔 ] [ 作者拉黑 ]`）；实际落地为**四个**
（用户拍板），把「营销味/AI腔」拆成两个独立 style flag——它们喂的是同一批通道，但不是同一种
毛病，合成一个值会让 C/D 通道再做一次同样的平均：

| chip（UI 文案） | 存的值 | 喂哪个通道 |
|---|---|---|
| 不感兴趣 | `topic` | B（话题 dense kNN） |
| 广告营销 | `promo` | C/D（文风 / 词面） |
| AI Slop | `ai_slop` | C/D（文风 / 词面） |
| 不喜欢作者 | `author` | A（作者先验） |

落地时定下、值得记住的几条契约（完整版在主计划的「Phase 3 补记」，决策理由在决策记录表的
「踩的理由 chip」一行）：

- **`item_feedback.reason` 可空列**，封闭枚举（入口 `Literal`，非法值 422）——自由文本没法当特征。
- **跳过零损失**：不选就是 NULL，退化成本来的 bag 级标签。所以它是一次追问，不是一道关卡；
  chips 之前打的标签也全是 NULL，不给它们编理由。
- **一次请求说清整条标签**：`POST /api/feedback` 不带 reason = 没有理由、会清掉已存的那个。
  否则把「踩 + AI Slop」改正成「赞」时，旧成因会跟着跑到正样本上——那正是要避免的脏数据。
- **UI 只回应「这一次点击」**：已标注的推文滚回视野不会再追问（web 是卡片下方一行 chips，
  iOS 是原生 `confirmationDialog`）。已选理由只在详情面板回显，卡片上不画。
- **up 侧暂不追问**（正面标签的信用分配问题同样存在，但列本身与 verdict 无关，将来要加是 UI
  改动而非迁移）。
- **判定管线今天不读 reason**：数据先攒，通道取舍等回测。

但没回流进 Phase 3 规格，07-25 实现的 Phase 3 只有裸 up/down，07-26 才补。

## 落地次序

⚠️ 以下 1–4 是 2026-07-24 按**成本**排的原次序；2026-07-27 的回测按**收益**把它重排成
C > D > A（理由见上一节）。原文保留，因为「先做便宜的」这个论证本身没错，只是被数据推翻了排序。

1. dense kNN 仍为 v1 baseline——最快跑起来的对照组，回测框架建其上。✅ 已回测：正向可用、负向下线。
2. 通道 A（作者先验）近零成本，与 baseline 同批。→ 回测后降级：只有 1 个 `author` 踩，缺乏训练信号。
3. 通道 C（LLM 属性提取）是「提取特征再标记」直觉的正身，预期收益最大，第二批；属性 taxonomy 先手写 ~20 个（尤其 style flags），跑一阵后让 LLM 提议扩充。→ **回测后升为第一优先**：它是负判定唯一的复活路径。
4. 通道 D 在 C 之后看回测——C 是 D 的语义化版本，两者有重叠，未必都要。→ `engagement_farming`（10 个踩）几乎是纯词面模式，可能不必等 C。
5. ~~down-reason chips 越早越值钱（Phase 3）~~ —— ✅ 已落地 2026-07-26（见上）。现在每个踩都带
   可选属性，通道 A/C/D 将来有的放矢；在此之前的标签是 bag 级的，回测时留意这个断层。
